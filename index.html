程式進化史

從一個想法到可以用的工具

每次遇到問題就改，每次改完又發現新問題。這就是 Vibe Coding 的過程。

V 0.1
起點

「OneDrive 應該有這個功能吧？」

最初只是想用 OneDrive 內建的 AI 分類功能。結果發現日本地區根本沒有「人物」「地點」這些功能。

✗OneDrive 日本地區無人臉分類功能
✗Google 相簿也被否決（不想搬平台）
→決定自己寫程式解決
V 0.2
第一次嘗試

Python？那是什麼？

Claude 生成了第一個 Python 腳本。問題是：要怎麼執行它？雙擊後視窗一閃就關掉。花了比寫程式更多的時間在搞執行環境。

→學到了 cmd 命令提示字元的用法
→學到了 pip install 的意義
!Python 3.14 太新，大部分 AI 套件不支援
V 1.0
第一個視窗

終於有視窗了

用 tkinter 做出第一個圖形介面。有瀏覽按鈕、進度條、分類統計。但人臉偵測用的是基礎 OpenCV，準確率只有 50-60%，人物和風景一直互相誤判。

✓tkinter 視窗正常開啟
✓人物 / 亂拍 / 重複 三分類
✗OpenCV Haar Cascade 準確率不足
V 1.5
AI 升級

換掉人臉偵測引擎

嘗試了 face_recognition（dlib 編譯失敗）、InsightFace（stringzilla 失敗），最後成功用 MediaPipe 0.10.7 換掉 OpenCV。準確率明顯提升。

✗dlib 在 Windows 編譯失敗
✗InsightFace 不支援 Python 3.14
✓MediaPipe 0.10.7 + Python 3.11 成功
!發現 Python 版本衝突問題（3.14 vs 3.11）
V 2.0
場景分類

加入 CLIP AI 場景分析

原本的「亂拍」太籠統了。用 OpenAI 的 CLIP 模型加入風景、食物、文件偵測，分類從 3 類擴展到 8 類，再加入客製分類「立式划槳」。

✓CLIP vit-base-patch32 場景分類
✓人物 / 風景 / 立式划槳 / 文件 / 截圖 / 影片 / 日常 / 重複
✓HEIC 格式（iPhone 照片）支援
!速度太慢，需要優化
V 2.5
現在

批次處理 + 月份選擇

加入批次 CLIP 推論（一次 8 張）、文字特徵預計算、月份範圍選擇器。速度提升 5~8 倍。影片直接移動不需 AI 分析。

✓批次處理，速度快 5~8 倍
✓月份範圍選擇（07月 → 12月）
✓影片副檔名直接分類，不讀取內容
✓同一資料夾內自動建立分類子資料夾

踩過的坑

失敗是過程，不是結局

每一個障礙都讓程式變得更好。

01

視窗一閃就關掉

雙擊 .py 檔案，視窗閃一下就消失。花了很長時間才搞清楚要用命令提示字元執行，然後又做了 .bat 啟動檔。

02

Python 版本地獄

電腦裝了 Python 3.14，但 MediaPipe 只支援到 3.11。最後兩個版本並存，用 py -3.11 指定執行。

03

OneDrive 雲朵圖示

照片在雲端沒有下載到本地，程式讀不到。研究了 Graph API、本機同步、隨選即用各種方案。

04

MediaPipe 一直顯示 OpenCV

程式載入順序問題，MediaPipe 初始化失敗但沒有錯誤訊息。最後改成背景執行緒初始化才解決。

05

HEIC 無法預覽

iPhone 拍的照片是 HEIC 格式，Pillow 預設不支援。加裝 pillow-heif 套件後解決。

06

速度太慢

CLIP 每張照片要 2~5 秒，100 張要 8 分鐘。改成批次處理 8 張 + 預計算文字特徵，速度快了 5~8 倍。

心得

我學到的三件事

你不需要懂技術，你需要懂問題

我不知道什麼是 MediaPipe、什麼是 CLIP、什麼是批次處理。 但我知道「分類不準」「速度太慢」「視窗關掉了」。 把問題說清楚，Claude 就能找到解法。

每次失敗都是下一個版本的原料

程式從 3 個分類變成 8 個，從沒有視窗變成有視窗， 從速度慢變成批次處理。每一個問題都讓它變得更好用。 如果一開始就完美，就不會有這個過程。

Vibe Coding 是對話，不是下指令

最有效的方式不是「幫我寫一個 XX 程式」， 而是把自己的情況、遇到的問題、想要的結果說清楚。 Claude 不是在幫你寫程式，是在跟你一起解決問題。

「Python 是什麼？」我在對話裡真的問過這個問題。 四年前開始堆的 72,447 個檔案，現在終於有工具可以整理了。
